## 보안

- Advanced Config에 `auth_request`가 남아 있는 호스트(v2.25.0 이전에 저장했거나 그때 백업에서 복원한 호스트)에서 GeoIP 챌린지 모드를 켜면, 그 로그인이 `location /`에서 빠져 로그인 없이 접속되거나 설정 검사가 실패해 호스트가 내려가던 문제. 이제 이런 호스트는 챌린지 대신 차단(403)하고 로그인은 그대로 둡니다.
- SSO(OIDC)에 쓰는 go-jose를 4.1.6으로 올렸습니다. 지나치게 큰 RSA 키로 처리를 붙잡아 두는 JWK를 거부하는 보안 수정(GHSA-mgcc-cww5-fp2q)입니다.

## 고침

- 익스플로잇 룰의 호스트별 예외를 없는 호스트나 룰에 추가하면 500 대신 404를, 잘못된 ID에는 400을 돌려줍니다. 없는 호스트의 룰 목록 조회와 예외 삭제도 404입니다.
- API 문서(swagger)의 `POST /api/v1/challenge/verify` 요청 형식이 실제와 달랐던 문제. 없는 `solution` 대신 `proxy_host_id`와 `challenge_reason`을 적었습니다.

## Security

- On a host whose Advanced Config still has an `auth_request` (saved before v2.25.0, or restored from a backup of that time), turning on GeoIP challenge mode dropped that login from `location /`, so visitors got in without it, or failed the config check and took the host offline. Such a host now blocks (403) instead of showing the challenge and keeps its login.
- go-jose, used for SSO (OIDC), is now 4.1.6. It rejects JWKs with oversized RSA keys that could tie up processing (GHSA-mgcc-cww5-fp2q).

## Fixed

- Adding an exploit rule exclusion for a host or rule that does not exist now returns 404 instead of 500, and a malformed ID returns 400. Listing the rules of, or removing an exclusion from, a host that does not exist is 404 too.
- The API docs (swagger) described the wrong body for `POST /api/v1/challenge/verify`: they asked for a `solution` field that does not exist and left out `proxy_host_id` and `challenge_reason`.
