## 수정

- 캐시를 "정적 파일만"으로 켠 호스트에서 `app.js?v=3`처럼 쿼리가 붙은 정적 파일이 캐시되지 않던 문제를 고쳤습니다. 반대로 `/?next=a.js`처럼 쿼리가 확장자로 끝나는 페이지는 캐시되고 있었는데, 이제 캐시하지 않습니다.
- `/account.php/x.css`, `/account;.js`처럼 정적 파일 주소 모양이지만 백엔드가 페이지로 답할 수 있는 경로는 "정적 파일만" 캐시에서 제외합니다.
- `Authorization` 헤더가 붙은 요청의 응답은 캐시에 저장하지 않습니다. 이전에는 저장되어 헤더 없는 다음 요청에 그대로 나갈 수 있었습니다.
- 캐시를 켰는데 프록시 버퍼링이 꺼져 있으면 nginx가 아무것도 저장하지 않습니다. 호스트 설정 화면이 이 경우를 경고로 알려줍니다.

## 개선

- 보안 규칙을 검사하는 데 드는 nginx CPU를 줄였습니다.
- 프록시 캐시를 마지막 사용 후 7일까지 보관합니다(이전 60분). 캐시가 쓰는 디스크가 늘 수 있습니다. 상한은 그대로 10GB이고, 디스크 여유가 1GB 아래로 내려가면 캐시부터 비웁니다.

---

> ```bash
> docker compose pull && docker compose up -d
> ```

## Fixes

- On a host caching "static files only", a static file requested with a query string (`app.js?v=3`) was never cached. A page whose query happened to end in an extension (`/?next=a.js`) was cached; it no longer is.
- Paths that look like a static file but may be answered with a page, such as `/account.php/x.css` or `/account;.js`, are left out of the "static files only" cache.
- Responses to requests carrying an `Authorization` header are not stored in the cache. They used to be stored and could be served to the next request without the header.
- With caching on and proxy buffering off, nginx stores nothing. The host form now warns about this.

## Improvements

- nginx spends less CPU checking security rules.
- The proxy cache keeps an entry for 7 days after its last use (was 60 minutes). The cache may use more disk. The cap is still 10 GB, and the cache is cleared first when less than 1 GB of disk is free.
