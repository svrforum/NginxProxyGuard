## ✨ New: get told when something breaks — Discord, Telegram, or any webhook

NPG can now send you alerts. **Settings → Notifications** connects a channel, and the panel walks you through the parts nobody remembers — how to get a Telegram bot token, how to find your chat id, where Discord hides "New Webhook". (#221)

Three channel types:

- **Telegram** — private chat, group, or broadcast channel. Press **Detect chat id** and NPG lists the conversations your bot can see, so you never have to hunt for a number Telegram shows nowhere.
- **Discord** — paste a webhook URL. Alerts arrive as embeds with a coloured bar.
- **Webhook** — for ntfy, Gotify, Apprise, Home Assistant or anything you built yourself. Pick **JSON** or **plain text** depending on what your receiver expects; the field says which is which.

### It stays quiet on purpose

The point of an alert is that you notice it, which stops being true at the fourth message about the same thing.

- **A problem is announced once**, when it starts, and once more when it recovers. A certificate that has been failing for a week is re-checked every six hours and says nothing in between.
- **Bursts are collapsed.** IP bans and refused sign-ins arrive as one message with a count, not one per event.
- **Each alert is yours to place.** Every one of the nine alerts can be set to **off**, **immediate**, or **summary only** — the last one holds it for the daily summary instead of buzzing your phone.

### A daily summary worth reading

Turn it on, pick an hour, and once a day you get the state of the box:

```
📊 Nginx Proxy Guard — last 24 hours

📋 Overview
  Requests: 4,556
  Proxy hosts active: 19 / 22
  Certificates: 16

🖥 Server resources
  CPU: 14%
  Memory: 7.1 GB / 14.9 GB (48%)
  Disk: 379.6 GB / 467.3 GB (86%)
  Database: 740.0 MB
  Uptime: 50d 1h

🛡 Blocked requests: 613
  geo_block: 433
  bot_filter: 43
  …

📜 Certificates expiring within 30 days
⚠️ Still failing
🔗 Open the dashboard: https://npg.example.com
```

Resource usage is in there because storage is what actually kills a home server: logs grow until the disk is full, and then nginx cannot write and Postgres cannot commit. Anything still broken keeps appearing here, which is the other half of the bargain "announced once" makes.

You can **send yourself the summary right now** from the channel's settings, built from real data, rather than waiting until the configured hour to find out whether it is useful.

### Messages you can read

Alerts lead with a glyph — 🔴 problem, 🟠 notice, ✅ resolved — and each channel is written in **its own language**, Korean or English, chosen per channel rather than following whoever happens to be looking at the panel. Telegram gets MarkdownV2, Discord gets embeds, webhooks get structured JSON with a human line inside. Or write your own one-line format with `{{host}}`, `{{detail}}` and friends.

Request headers, cookies, user-agents and full request URLs are deliberately **not** available as placeholders. A notification leaves your network by definition, and credentials turn up in those fields.

### When a channel breaks

- The card says why, and names how many failures remain before NPG switches the channel off.
- **Delivery history** per channel answers "why did I not get an alert" — every attempt, its status, and the error.
- A receiver that is merely *down* — an ntfy container restarting, a Telegram rate-limit — no longer counts against that limit. Only failures NPG will not retry do.
- A channel that did switch itself off says so in the container log, and comes back the moment a test send succeeds.

## 🩹 Fixes

- Alerts and the summary named a broken certificate by its database id. They now name the domain.
- The daily summary hour is labelled with the **server's** timezone. It was labelled with your browser's, while the schedule follows the API container's clock — set 9 from Seoul on a default install and the summary arrived at 18:00 local. If the two differ, the field now says so.
- Telegram chat detection could not see broadcast channels at all, so **Detect chat id** dead-ended with "send it a message and try again".
- Long forms keep their title and **Save** button in view while the body scrolls. Saving from the bottom of the notification form used to look like nothing happened, because the error appeared off-screen above.
- IP-ban alerts fired for fail2ban but not for WAF auto-ban, though the description promised both.
- Validation messages in the notification form are translated instead of quoting the API's field names.
