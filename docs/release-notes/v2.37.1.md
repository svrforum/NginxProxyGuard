## 🩹 수정

### Authelia 등 클레임을 토큰에 담지 않는 공급자로 로그인 (#238)

Authelia에서는 기존 계정 연결이 아예 동작하지 않았고, 자동 계정 생성도 "이메일이 없다"며 모든 로그인을 거부했습니다. 공급자는 이메일을 보내고 있었는데도요.

NPG가 **ID 토큰만** 읽었기 때문입니다. Authelia는 기본 claims policy에서 `email`·`name`·`groups`를 **UserInfo 응답**에만 넣습니다. NPG 입장에서는 이메일이 오지 않은 것과 같았습니다. 이제 토큰에 없는 클레임은 UserInfo에서 가져옵니다.

ID 토큰이 말한 값은 그대로 우선하고, 다른 사용자에 대한 응답은 폐기하며, UserInfo를 지원하지 않는 공급자는 이전과 똑같이 동작합니다 — 이미 잘 되던 Google·Dex·Keycloak 설정은 영향받지 않습니다.

실제 Authelia로 확인했습니다: 수정을 빼면 일치하는 로컬 계정이 있는데도 "이 신원에 연결된 NPG 계정이 없습니다"로 실패하고, 수정을 넣으면 계정이 연결되며 대시보드까지 들어갑니다.

### 상세 상태 페이지가 로그 행 수를 81% 적게 보고하던 문제

`/api/v1/health/detailed`가 실제 1,029,800행에 대해 194,167행으로 보고했습니다. 청크가 압축되면 원본이 비워지기 때문에, 기존 추정 방식은 **압축 정책이 이미 지나간 데이터를 세지 못했습니다.** 시간이 갈수록 오차가 커지는 구조였습니다.

이제 압축된 청크에서 직접 행 수를 셉니다. 같은 테이블이 실제 1,029,803행에 대해 1,028,246행으로 보고합니다.

### 잘못된 요청으로 WAF 규칙을 끄면 범위가 넓어지던 문제

규칙 비활성화 요청의 JSON 본문이 깨져 있으면 **본문이 없는 것과 동일하게** 처리됐습니다. 본문이 없다는 건 "이 호스트 전체에서 끄기"라는 뜻이라, **한 경로에서만 끄려던 요청이 오타 하나로 호스트 전체에서 꺼질 수 있었습니다.** 빈 본문은 그대로 호스트 전체를 뜻하고, 깨진 본문은 이제 거부합니다.

## 🩹 Fixes

### Signing in with Authelia, and other providers that keep claims out of the token (#238)

Linking an existing account never worked on Authelia, and automatic account creation refused every sign-in for a missing email address — even though the provider was sending one.

NPG only read the ID token. Authelia's default claims policy puts `email`, `name` and `groups` in the **UserInfo** response instead, so as far as NPG was concerned the provider had returned no email at all. NPG now asks the UserInfo endpoint for whatever the token did not carry.

The ID token still wins wherever it says something, a response about a different subject is discarded, and a provider that does not answer UserInfo is left exactly as it was — so Google, Dex and Keycloak setups that already worked are untouched.

Verified against a real Authelia instance: with the fix removed the sign-in fails with "no NPG account is linked to this identity" even though the matching local account exists; with it in place the account links and the dashboard loads.

### The detailed health page was under-reporting log rows by 81%

`/api/v1/health/detailed` reported 194,167 access-log rows against an actual 1,029,800. Compressing a chunk empties its heap, so the row estimate it relied on stopped counting everything the compression policy had already touched — and the gap widened every day.

Compressed rows are now counted from the compressed chunks themselves. The same table now reports 1,028,246 against an actual 1,029,803.

### Disabling a WAF rule with a malformed request no longer widens it

Sending a malformed JSON body to the disable-rule endpoint was treated as sending no body at all, which means "switch this rule off for the whole host". A client asking to switch a rule off for a single path could therefore have it switched off everywhere because of a typo. An empty body still means whole-host; a malformed one is now rejected.
