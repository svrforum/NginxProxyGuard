## 🛡️ Bug Fix — Cloudflare Tunnel with an HTTPS origin

Fixes the tunnel failing for every proxy host when the Cloudflare Public Hostname points at `https://localhost:<port>` (#209).

The default HTTPS server rejects unknown TLS SNI (`ssl_reject_handshake on`, an anti-scan hardening). The Cloudflare Tunnel connector reaches nginx over `https://localhost`, whose SNI (`localhost`) matches no proxy host — so the handshake was aborted with:

```
remote error: tls: unrecognized name   originService=https://localhost:443
```

and all proxied hosts errored over the tunnel.

NPG now runs a dedicated **loopback HTTPS server** (`server_name localhost`) with a self-signed certificate, so the tunnel's loopback handshake completes and requests are then routed to the correct proxy host by their `Host` header. Every **other** unknown SNI is still rejected, so the anti-scan behavior is unchanged.

Verified: SNI `localhost` handshake now succeeds and routes to the matching host; an unknown scanner SNI is still rejected; `nginx -t` passes.

> ⚠️ **This fix spans both the nginx and api images** — pull all three and recreate:
> ```bash
> docker pull svrforum/nginxproxyguard-nginx:2.32.2
> docker pull svrforum/nginxproxyguard-api:2.32.2
> docker pull svrforum/nginxproxyguard-ui:2.32.2
> docker compose up -d
> ```
