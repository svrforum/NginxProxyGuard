## 🚀 New Feature: Cloudflare Tunnel

Expose your proxy hosts to the internet **without opening a single inbound port**. NPG now ships a built-in `cloudflared` connector that makes an *outbound-only* connection to Cloudflare's edge — visitor traffic flows back through the tunnel and still passes through NPG's full security stack (WAF / ModSecurity, GeoIP, rate-limiting, ban lists), with real visitor IPs preserved.

![Cloudflare Tunnel settings](https://raw.githubusercontent.com/svrforum/NginxProxyGuard/v2.32.0/docs/release-notes/assets/v2.32.0/tunnel-settings.png)

**How it works**

- Create a tunnel in the Cloudflare Zero Trust dashboard and paste the connector token — or paste the **whole `cloudflared` install command** and NPG extracts the token automatically. Toggle it on and save. No `docker-compose` changes required.
- **One tunnel covers every host.** A single wildcard Public Hostname (`*.example.com`) is enough — NPG routes each request to the right proxy host by its `Host` header.
- The connector runs inside the nginx container over the host network, so the tunnel origin is simply NPG itself.

**Built-in setup guide** — shows the exact origin URL for *your* install (it reflects your configured HTTPS/HTTP ports) and calls out the two gotchas that trip people up: Cloudflare's first-match Public Hostname ordering, and HTTP-only hosts.

![Setup guide with warnings](https://raw.githubusercontent.com/svrforum/NginxProxyGuard/v2.32.0/docs/release-notes/assets/v2.32.0/tunnel-setup-guide.png)

> ⚠️ **Upgrading? Pull the nginx image too.** The tunnel connector lives inside the nginx image, so pull all three:
> ```bash
> docker pull svrforum/nginxproxyguard-nginx:2.32.0
> docker pull svrforum/nginxproxyguard-api:2.32.0
> docker pull svrforum/nginxproxyguard-ui:2.32.0
> ```
> An older nginx image has no tunnel supervisor, so enabling the tunnel would silently do nothing.

## 🛡️ Bug Fixes

- **Proxy host delete/create no longer leaves a "zombie" nginx config under concurrency.** A host deleted while a config regeneration was in flight could have its config resurrected and left behind, poisoning `nginx -t` system-wide until the next manual *Sync All*. Delete/rollback now update the database first so the drift sweep is authoritative, and a failed config cleanup is surfaced instead of silently reported as success.
- **System logs now capture container startup logs on a cold `docker compose up`.** Previously only the nginx source appeared until you restarted every container; other sources (API, DB, UI) were missing because their startup burst was emitted before the log collector attached. The collector now reaches back to each container's start time. ([#205](https://github.com/svrforum/NginxProxyGuard/issues/205))
- Localized the global-default audit-log action labels (Korean / English).
