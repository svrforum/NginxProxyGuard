## 🩹 수정

### v2.37.1이 자기 버전을 2.37.0으로 표시하던 문제

v2.37.1 이미지는 `/health` 응답과 화면 하단에서 자신을 **2.37.0**으로 보고했습니다. 릴리즈 커밋에 버전 파일이 들어가지 않은 탓입니다. 기능은 모두 정상이었지만, 어떤 버전이 돌고 있는지 확인할 수 없었습니다.

이번 릴리즈부터는 버전을 담은 네 파일이 **태깅 전에 커밋된 내용 기준으로** 검사됩니다. 작업 폴더만 확인하면 이번 같은 경우를 놓칩니다.

### API 명세의 버전 표기

`/api/docs`가 내려주는 OpenAPI 명세의 `info.version`이 2.36.0에 멈춰 있었습니다. API 클라이언트를 만드는 분이 "이 문서가 지금 서버를 설명하는가"를 판단하는 첫 값이라, 이제 릴리즈 버전과 함께 올라갑니다.

## 🔒 저장소 보안

공개 저장소의 PII 검사가 위반을 발견했을 때 **해당 값을 더 이상 로그에 출력하지 않습니다.** 공개 저장소의 Actions 로그는 누구나 볼 수 있고 히스토리 정리 이후에도 남기 때문에, 값을 출력하면 유출에 두 번째 사본을 만들어 주는 셈이었습니다. 이제 파일과 줄 번호(또는 커밋 해시)만 알리고, 값은 로컬에서 확인하도록 안내합니다.

> docker compose pull && docker compose up -d
> ```

## 🩹 Fixes

### v2.37.1 reported itself as 2.37.0

The v2.37.1 image reported version **2.37.0** in its `/health` response and in the UI footer, because the version files never made it into the release commit. Everything worked, but there was no way to tell which build was running.

From this release the four files that carry the version are checked **against the commit** before tagging. Checking the working folder alone misses exactly this case.

### The API specification's version

The `info.version` in the OpenAPI document served at `/api/docs` was still 2.36.0. It is the first value an API client author reads to decide whether the document describes the server they are talking to, so it now moves with the release.

## 🔒 Repository security

The PII check no longer prints the offending value when it finds one. Actions logs on a public repository are public and outlive a history rewrite, so echoing the value handed a leak a second home. It now reports the file and line — or the commit hash — and points at the local tool for the value itself.
