## 🐛 Bug Fix

- **Geo/cloud challenge redirects now stay HTTPS on SSL hosts behind a TLS-terminating proxy.** The challenge redirect built its post-challenge `return` URL from nginx's raw `$scheme`. Behind a proxy that terminates TLS and forwards to the origin over HTTP (e.g. **Cloudflare with "Flexible" SSL**), nginx sees `$scheme=http`, so an SSL host produced `return=http://…` on an otherwise HTTPS page — which the browser blocked as **Mixed Content**, preventing the Turnstile/challenge widget from loading. SSL hosts now pin `https` in the challenge redirect (the same fix already applied to Forward Auth in v2.27.1); plain HTTP hosts are unchanged. (#213)

> docker compose pull && docker compose up -d
> ```
