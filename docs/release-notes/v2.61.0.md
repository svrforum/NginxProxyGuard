## ⚠️ 업그레이드 전에 알아둘 것

- **"접속 로그 활성화"(전역 설정)를 꺼 둔 설치는 업그레이드 후 접속 로그가 다시 DB에 쌓입니다.** 이 스위치를 끄면 docker logs 사본뿐 아니라 로그 화면·대시보드·차단 기능이 쓰는 수집까지 멈추고 있었습니다. 이제는 docker logs 사본만 끄고, 이름도 "접속 로그를 docker logs에도 출력"으로 바뀝니다.
- 로그 압축 시점이 기본값(7일) 그대로면 1일로 바뀝니다. 업그레이드 후 첫 압축 때 밀린 날짜를 한꺼번에 압축하느라 잠시 CPU와 디스크를 더 씁니다. 직접 바꾼 값은 그대로 둡니다.
- 원본 로그 파일은 이제 "보관 기간(일)"대로 지우고, "회전 파일 수" 설정은 없어집니다. 업그레이드 때 보관 기간을 기존 파일 수만큼 한 번 늘리되, 설치 후 지난 날수까지만 늘립니다. 파일 수를 크게 잡아 두었다면 업그레이드 후 보관 기간을 확인하세요.
- 챌린지 기록도 접속 로그 보관 기간을 따릅니다. 그보다 오래된 기록은 지워집니다.
- 클라우드 제공자 챌린지 호스트도 v2.60.1의 지역 챌린지와 같아집니다. 접근 목록이 모든 방문자에게 적용되고, 고급 설정 location도 챌린지를 거칩니다. 인증 제공자(ForwardAuth)를 쓰는 호스트는 챌린지 대신 403을 보냅니다.

## 새 기능

- 디스크 감시: DB·nginx 로그·백업·Docker가 쓰는 디스크를 1분마다 확인해 대시보드에 경고를 띄우고, 85%·90%·복구 시 알림을 보냅니다(알림 설정에서 디스크 이벤트를 구독해야 갑니다). DB 디스크가 90%를 넘으면 지난 로그를 바로 압축합니다.
- 회전된 원본 로그를 다른 디스크나 NAS로 옮길 수 있습니다. 로그 > 원본 파일 > 보관 디렉터리.
- 설정 > 유지보수에서 압축된 과거 로그의 원문 사본을 지워 DB 공간을 되찾을 수 있습니다. 선택 사항이고 되돌릴 수 없습니다.

## 고침

- 보안: 지역·클라우드 챌린지 호스트에서 레이트 리밋 응답을 503으로 설정했거나 전역 동시 연결 제한에 걸린 요청이 챌린지 없이 원본 서비스로 가던 문제.
- 클라우드 제공자 챌린지를 풀어도 계속 챌린지 페이지로 돌아가던 문제.
- 챌린지를 통과한 방문자가 대시보드와 일일 요약에서 차단으로 집계되던 문제.
- 대시보드 요청 수가 일부 요청을 두 번 세거나 빠뜨리던 문제. 업그레이드 때 최근 25시간을 다시 계산하므로 수치가 달라 보일 수 있습니다.
- 원본 로그가 크기 제한을 넘어 한 파일이 수 GB까지 커지던 문제. 이제 매시간 크기를 확인합니다.
- nginx 컨테이너만 재시작하거나 nginx가 API보다 먼저 뜰 때 원본 로그 기록이 꺼지던 문제.
- 업그레이드 직후 nginx.conf가 이전 버전 그대로 남던 문제. 이제 nginx가 뜨면 바로 새 설정을 적용합니다.
- TimescaleDB 2.30에서 상세 상태 점검이 DB를 연결 끊김으로 보고하던 문제.
- 만료된 챌린지 토큰이 지워지지 않고 계속 쌓이던 문제.

## ⚠️ Read before upgrading

- **If you turned off "Enable Access Log" (Global Settings), access logs reach the database again after the upgrade.** The switch was stopping not only the docker logs copy but also the collection the log viewer, dashboard and blocking features rely on. It now turns off the docker logs copy only, and is renamed "Also print access log to docker logs".
- Logs are now compressed after 1 day if the setting is still at its default of 7 days. The first compression run after the upgrade compresses the days in between at once, which takes extra CPU and disk for a while. A value you set yourself is kept.
- Raw log files are now deleted by "retention days", and the "rotated file count" setting is gone. The upgrade raises the retention once to match the old file count, but no further than the install's age in days. If you kept a large file count, check the retention after the upgrade.
- Challenge records now follow the access log retention. Older records are deleted.
- Hosts with the cloud provider challenge now behave like geo-challenge hosts since v2.60.1: access lists apply to every visitor, and Advanced Config locations are challenged too. Hosts with an auth provider (ForwardAuth) answer 403 instead of the challenge.

## New

- Disk watch: the disks used by the database, nginx logs, backups and Docker are checked every minute. The dashboard warns, and alerts go out at 85%, 90% and on recovery (subscribe to the disk events in notification settings). Above 90% on the database disk, older logs are compressed right away.
- Rotated raw logs can be moved to another disk or a NAS: Logs > Raw files > Archive directory.
- Settings > Maintenance can delete the verbatim copies kept in older compressed logs to free database space. Optional and irreversible.

## Fixed

- Security: on hosts with the geo or cloud provider challenge, requests refused by a rate limit set to answer 503, or by the global connection limit, reached the protected service without the challenge.
- Solving the cloud provider challenge sent visitors back to the challenge page.
- Visitors who had passed a challenge were counted as blocked on the dashboard and in the daily digest.
- Dashboard request counts counted some requests twice and missed others. The upgrade recalculates the last 25 hours, so the numbers may change.
- Raw logs grew past their size limit, up to several GB per file. Size is now checked every hour.
- Restarting only the nginx container, or nginx starting before the API, turned raw logging off.
- After an upgrade, nginx.conf stayed on the previous version. It is now applied as soon as nginx is up.
- On TimescaleDB 2.30 the detailed health check reported the database as disconnected.
- Expired challenge tokens were never deleted.
