## ⚠️ Valkey 없이 쓰는 설치: 업그레이드 후 API·로그인 요청 수 제한이 새로 걸립니다

`REDIS_URL`을 비워 Valkey 없이 쓰셨다면, 지금까지는 분당 API 요청 제한과 로그인 시도 제한이 동작하지 않았습니다. 이번 버전부터는 Valkey가 없으면 API가 자체 메모리로 캐시와 카운터를 운영해서, 클라이언트 IP마다 **API 분당 600회, 로그인 분당 100회** 제한이 걸립니다. Valkey를 쓰는 설치(기본 구성)는 달라지는 것이 없습니다. (#385)

- 관리 화면에 429(요청이 너무 많음)가 보이면 `API_RATE_LIMIT_PER_MINUTE`를 올리거나 `0`으로 끄세요. 로그인 쪽은 `AUTH_RATE_LIMIT_PER_MINUTE`입니다.
- `TRUSTED_PROXY_CIDR`를 설정해 두셨다면 관리 화면 앞에 있는 프록시의 주소가 들어 있는지 확인하세요. 빠져 있으면 모든 접속이 그 프록시 한 곳에서 온 것으로 세어져 함께 제한에 걸립니다.
- 세 값 모두 `docker-compose.yml`의 api 환경 변수입니다. 예전 compose 파일에 해당 줄이 없으면 현재 [docker-compose.yml](https://github.com/svrforum/NginxProxyGuard/blob/main/docker-compose.yml)을 참고해 추가하세요.

## ⚠️ Installs without Valkey: API and sign-in rate limits now apply after upgrading

If you run NPG without Valkey (`REDIS_URL` empty), the per-minute API and sign-in limits never took effect until now. From this version the API keeps its caches and counters in its own memory when Valkey is absent, so each client IP gets **600 API requests and 100 sign-in attempts per minute**. Installs that use Valkey (the default setup) see no change. (#385)

- If the admin panel shows 429 (Too Many Requests), raise `API_RATE_LIMIT_PER_MINUTE` or set it to `0` to turn the limit off. Sign-in has its own `AUTH_RATE_LIMIT_PER_MINUTE`.
- If you set `TRUSTED_PROXY_CIDR`, make sure it includes the proxy in front of the admin panel. Without it, every visitor is counted as that one proxy and they share a single limit.
- All three are api environment variables in `docker-compose.yml`. If your compose file predates them, add the lines from the current [docker-compose.yml](https://github.com/svrforum/NginxProxyGuard/blob/main/docker-compose.yml).

## New features

- Global Fail2ban has a "Never ban local network addresses" switch. When on, no jail bans private or link-local addresses. It is off by default. (#384)
- Infomaniak is available as a DDNS provider. It is DDNS only, so it cannot be picked for certificates. (#382)
- OVHcloud is available as a DNS challenge provider for certificates. (#388)
- The log detail shows the host and the port the request arrived on. The port appears for requests logged after the upgrade. (#389)
- Installs without Valkey now cache too. (#385)

## Fixes

- The log detail always showed "-" for protocol, referer, city, ASN, and the WAF rule severity and attack type. (#389)
- Log entries from local addresses showed a broken flag next to the country.
