## 🔑 API 토큰

### 모니터링에 쓰는 엔드포인트가 API 토큰을 받습니다

API 토큰(`ng_...`)으로 아래 세 곳을 부르면 **401**이 났습니다. 명세에는 된다고 적혀 있어서, 토큰으로 클라이언트를 만드신 분들이 정작 가장 필요한 호출에서 막혔습니다.

- `GET /api/v1/auth/me` — 이 토큰이 누구 것인지
- `GET /api/v1/status` — API·DB·nginx 상태
- `GET /api/v1/health/detailed` — 상세 상태

라우트가 세션 전용 그룹에 묶여 있어 토큰 인증이 아예 거치지 않았던 것이 원인입니다. 이제 **토큰과 세션 둘 다** 됩니다.

**다만 계정을 다루는 곳은 일부러 세션 전용으로 두었습니다.** 비밀번호·사용자명·자격증명 변경과 2FA, 그리고 언어·글꼴 설정입니다. 토큰은 스크립트나 모니터링 시스템에 붙여 두는 오래 사는 비밀번호에 가깝습니다. 그런 토큰으로 비밀번호를 바꿀 수 있다면, 토큰 하나 새는 것이 **계정을 통째로 잃는 일**이 됩니다.

`POST /api/v1/health/canary`도 세션 전용입니다. 이름은 점검처럼 보이지만, 실패하면 자가복구가 돌면서 nginx 설정을 다시 쓰고 reload하며, 그 복구 횟수는 정기 점검과 나눠 씁니다.

### `/auth/me`가 알려주던 권한이 틀렸습니다

토큰으로 `/auth/me`를 부르면 **토큰의 권한이 아니라 토큰 주인의 권한**이 나왔습니다. 실제 판정은 *토큰 권한 ∩ 주인 권한*이라, `logs:read` 하나만 가진 토큰에게 "관리자이고 권한 35개"라고 답하면서 정작 다른 요청은 전부 거부하는 상태였습니다.

이제 그 토큰으로 **실제 쓸 수 있는 것만** 나옵니다.

```
logs:read 토큰   →  is_superuser: false,  ["logs:read"]
전체 권한 토큰   →  is_superuser: true,   전체 목록
```

`effective_permissions`를 보고 무엇을 시도할지 정하는 클라이언트라면 동작이 달라집니다.

### API 명세

인증 방식이 두 가지인데 명세에는 하나뿐이라 생긴 문제였습니다. 이제 **`SessionAuth`** 가 세션 전용 11개 연산에 표시되고, `BearerAuth`는 둘 다 받는다는 뜻으로 명확해졌습니다. 명세로 클라이언트를 생성하시면 "토큰으로 된다"는 잘못된 약속이 사라집니다.

> 정확한 원인 분석과 함께 신고해 주신 **@four2mis** 님 감사합니다. (#249)

## 🔒 보안

**Go 툴체인을 1.26.6으로 올렸습니다.** `crypto/tls`·`encoding/asn1`·`encoding/xml`·`html/template`·`net`·`net/http`·`net/url` 보안 수정과 CVE-2026-56865(체크섬 DB 위조를 통한 모듈 캐시 오염)가 포함됩니다. 툴체인이 표준 라이브러리를 바이너리에 넣기 때문에, 핀이 낡으면 수정도 낡은 채로 나갑니다.

## 🔑 API tokens

### The endpoints you monitor with now accept an API token

Calling these three with an API token (`ng_...`) returned **401**, while the specification said they should work — so anyone building a client around tokens was blocked on the calls they need most.

- `GET /api/v1/auth/me` — whose token is this
- `GET /api/v1/status` — API, database and nginx status
- `GET /api/v1/health/detailed` — detailed status

The cause was grouping: those routes sat in a session-only group that the API-token middleware was never attached to. They now accept **either credential**.

**Account management stays session-only, deliberately.** That means password, username and credential changes, the 2FA endpoints, and the language and font preferences. A token is a long-lived secret that gets pasted into scripts and monitoring systems; if one could change a password, a single leaked token would mean **losing the account**, not leaking information.

`POST /api/v1/health/canary` is session-only too. It reads like a probe, but a failing run invokes the self-healer, which rewrites nginx config and reloads it, drawing on a heal budget shared with the scheduled probe.

### `/auth/me` was reporting the wrong permissions

Called with a token, it reported the **token owner's** permissions rather than the token's. What is actually enforced is *token scopes ∩ owner's role*, so a token scoped to `logs:read` was told it was a superuser with all 35 permissions while every other request was refused.

It now reports what that token can actually use.

```
logs:read token   →  is_superuser: false,  ["logs:read"]
full-scope token  →  is_superuser: true,   the full list
```

If your client reads `effective_permissions` to decide what to attempt, its behaviour changes.

### The specification

One authentication scheme was describing two behaviours. There are now two: **`SessionAuth`** marks the eleven session-only operations, and `BearerAuth` means both credentials are accepted. Generated clients stop promising that a token will work where it will not.

> Thanks to **@four2mis** for the report, which came with the root cause already traced. (#249)

## 🔒 Security

**The Go toolchain moves to 1.26.6**, carrying stdlib security fixes to `crypto/tls`, `encoding/asn1`, `encoding/xml`, `html/template`, `net`, `net/http` and `net/url`, plus CVE-2026-56865 (checksum-database forgery leading to module-cache poisoning). The toolchain compiles the standard library into the binary, so a stale pin ships stale fixes.

Automated updates had instead offered a **release candidate** (1.27rc2), which was declined: RC tags are frozen rather than patched, so taking it would have moved *away* from the fixes above. Prereleases are no longer proposed; stable patch updates still come through.
