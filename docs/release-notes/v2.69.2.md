## 보안

- WAF 로그에 로그인 비밀번호·토큰·쿠키 값이 그대로 저장되던 문제. WAF 규칙이 로그인 폼 같은 요청에 걸리면 그 값이 WAF 로그 보존 기간 동안 남았습니다.
  - 새로 쌓이는 WAF 이벤트는 비밀값처럼 보이는 항목(쿠키, 요청 본문, 이름에 password·token·key·auth 등이 들어간 인수와 헤더)의 값을 `[redacted]`로 저장합니다. 변수 이름은 남아 있어 오탐 예외를 만드는 데 지장이 없습니다.
  - 이미 저장된 이벤트는 WAF 이벤트 상세 화면에서 가려 보여 줍니다. DB에 있는 기존 기록 자체는 업그레이드가 다시 쓰지 않으며, 보존 기간이 지나면 지워집니다.
- 오류 로그 레벨을 info나 debug로 설정했을 때 ModSecurity 규칙 경고 줄(요청 값 포함)이 로그 DB에 저장되던 문제. 같은 내용은 WAF 이벤트에 있으므로 더는 저장하지 않습니다.

## Security

- WAF logs stored login passwords, tokens and cookie values as sent. When a WAF rule fired on a request such as a login form, the value stayed for as long as WAF logs are kept.
  - New WAF events store `[redacted]` for values that look secret: cookies, the request body, and arguments and headers whose name says password, token, key, auth and the like. The variable names stay, so tuning false positives is unaffected.
  - Events already stored are shown redacted in the WAF event details. The upgrade does not rewrite the stored rows themselves; they go when their retention period ends.
- With the error log level set to info or debug, ModSecurity's per-rule warning lines, request values included, were stored in the log database. The WAF event holds the same, so they are no longer stored.
