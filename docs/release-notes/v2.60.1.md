## ⚠️ 업그레이드 전에 알아둘 것

지역 챌린지를 쓰는 호스트에서 바뀌는 것:
- **접근 목록이 있는 호스트는 이제 목록에 없는 IP를 거부합니다.** 지금까지는 챌린지 대상이 아닌 방문자에게 접근 목록이 적용되지 않았습니다. 목록이 허용한 IP라도 챌린지 대상이면 챌린지를 풀어야 합니다. 챌린지를 건너뛰게 하려면 지역 제한의 우선 허용 목록을 쓰세요.
- 고급 설정으로 추가한 location도 이제 챌린지를 거칩니다. 그 location에 자체 `error_page`가 있으면 챌린지 대신 401이 나갈 수 있습니다.
- "검색봇 허용"이 봇 필터를 켜지 않아도 동작합니다.
- 챌린지 페이지 요청 자체는 접근 로그에 남지 않습니다. 같은 방문이 두 번 세어지고 있었기 때문에, 대시보드의 차단·전체 요청 수가 줄어 보일 수 있습니다.

WAF:
- WebSocket 연결도 이제 다른 요청처럼 WAF가 검사합니다. 기본 민감도(PL1)에서는 달라지는 것이 없습니다. PL2 이상에서 WebSocket 연결이 막히면 WAF 로그에 나온 규칙을 그 호스트의 예외로 추가하세요.
- nginx 컨테이너가 시작할 때 `modsec/custom-rules.conf`의 NPG 기본 규칙만 고칩니다. 직접 추가한 규칙은 그대로 두고, 바뀌기 전 파일은 `custom-rules.conf.pre-v2.60.1`로 남깁니다.

## 고침

- 보안: 지역 챌린지를 풀지 않고 통과할 수 있던 문제.
- 보안: 경로가 상태 점검·Socket.IO 주소처럼 시작하기만 하거나 WebSocket 헤더만 단 요청이 WAF 검사를 건너뛰던 문제.
- WAF가 큰 페이지에서 걸린 뒤 WAF 이벤트 기록과 WAF 자동 차단이 멈출 수 있던 문제.
- 원본 로그가 회전되는 순간 접근 로그 몇 줄이 DB에 들어가지 않던 문제.
- 차단 IP 화면의 영구·자동 차단 수가 현재 페이지만 세던 문제. (#319)

## 저장 공간

- 접근·오류 로그의 원문 한 줄을 DB에 따로 저장하지 않습니다. 원문은 원본 로그 파일에 그대로 있습니다. 로그 DB가 늘어나는 속도가 크게 줄어듭니다.
- ModSecurity는 룰에 걸린 요청만 감사 기록을 남깁니다. 저장하는 WAF 기록에서는 쿠키·인증 헤더·요청과 응답 본문을 뺍니다.
- `/metrics`의 `npg_log_collector_watchdog_restart_total`에서 `reason="idle"`이 없어지고 `reason="stall"`이 생깁니다.

## ⚠️ Read before upgrading

On hosts that use the geo challenge:
- **Hosts with an access list now refuse IPs that are not on the list.** Until now the list was not applied to visitors the challenge did not target. An IP the list allows still has to solve the challenge when it is challenged; to let an address skip the challenge, put it in the geo restriction's priority allow list.
- Locations added through Advanced Config are now challenged too. A location with its own `error_page` may answer 401 instead of showing the challenge.
- "Allow search bots" now works without the bot filter.
- Requests for the challenge page itself are no longer access-logged. The same visit used to be counted twice, so blocked and total counts on the dashboard can look lower.

WAF:
- WebSocket connections are now inspected by the WAF like any other request. Nothing changes at the default paranoia level (PL1); at PL2 or higher, if a WebSocket connection is blocked, add the rule shown in the WAF log as an exclusion for that host.
- When the nginx container starts it updates only NPG's own rules in `modsec/custom-rules.conf`. Rules you added stay as they are, and the previous file is kept as `custom-rules.conf.pre-v2.60.1`.

## Fixed

- Security: the geo challenge could be passed without solving it.
- Security: requests whose path merely started like the health-check or Socket.IO endpoints, or that only carried a WebSocket upgrade header, skipped WAF inspection.
- WAF event logging and WAF auto-ban could stop after a WAF match on a large page.
- A few access-log lines written while the raw log rotated never reached the database.
- The banned IP screen counted permanent and automatic bans on the current page only. (#319)

## Storage

- The verbatim access and error line is no longer stored a second time in the database; it stays in the raw log files. The log database grows much more slowly.
- ModSecurity writes audit records only for requests that matched a rule, and stored WAF records no longer keep cookies, authorization headers or request and response bodies.
- In `/metrics`, `npg_log_collector_watchdog_restart_total` loses `reason="idle"` and gains `reason="stall"`.
