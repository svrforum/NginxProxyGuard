## 🩹 수정

### Authentik 계정 연결이 "이메일 미검증"으로 막히던 문제

이메일을 양쪽 다 맞췄는데도 로그인이 거절되고, 로그에는 이렇게만 남았습니다.

```
SSO: no account for provider "authentik" — email present=true, verified=false
```

주소는 오는데 **"검증됨" 표시가 없다**는 뜻입니다. 원인은 NPG 쪽에 있었습니다.

OpenID Connect에서 `email_verified`는 **선택 항목**입니다. 그래서 공급자에 따라 ID 토큰에는 주소만 담고, 검증 여부는 UserInfo 응답에만 넣기도 합니다. NPG는 이 항목이 **없는 것**과 **false인 것**을 구분하지 못해 둘 다 미검증으로 처리했고, UserInfo에서 값을 가져오는 경로도 *주소 자체가 비어 있을 때만* 동작해서 검증 표시는 영영 도착하지 못했습니다.

이제 **ID 토큰이 아무 말도 하지 않았을 때만** UserInfo에서 검증 여부를 가져옵니다. 안전장치도 함께 넣었습니다.

- ID 토큰이 **명시적으로 false**라고 했다면 그대로 존중합니다(서명된 값이 우선)
- UserInfo가 **다른 주소**에 대해 검증됐다고 말해도 지금 주소에는 적용하지 않습니다

Authentik·Authelia 등에서 계정 연결이 막혀 계셨다면 업데이트 후 다시 시도해 보세요. 여전히 `verified=false`가 나온다면 공급자에서 실제로 미검증 상태인 것이니, 해당 사용자의 이메일을 검증 처리해 주시면 됩니다.

> 로그까지 정확히 보내 주신 **@heygoodluck** 님 감사합니다. (#248)

## 🩹 Fixes

### Authentik account linking was blocked as "email not verified"

The address matched on both sides, the sign-in was still refused, and the log said only this:

```
SSO: no account for provider "authentik" — email present=true, verified=false
```

The address arrives, but with no **verified** flag. The cause was on NPG's side.

`email_verified` is **optional** in OpenID Connect, so some providers put the address in the ID token and assert the verification flag only in the UserInfo response. NPG could not tell **absent** from **false** and treated both as unverified — and the path that fills claims from UserInfo only ran when the address itself was missing, so the flag could never arrive.

The flag is now taken from UserInfo **only when the ID token said nothing about it**, with two guards:

- An **explicit false** in the ID token is never overridden — the signed value wins.
- A UserInfo response about a **different address** cannot mark this one verified.

If account linking was blocked for you on Authentik, Authelia or similar, update and try again. If it still reports `verified=false`, the provider really is reporting the address as unverified — mark that user's email verified on the provider side.

> Thanks to **@heygoodluck**, who sent the exact log that made this findable. (#248)

## ✨ Improvements

### Click an IP in the ban history to see its statistics

In the banned IP **list**, clicking an address showed its country, request counts and the hosts and paths it went after. In the **ban history** tab and the **top banned IPs** list, the same addresses were plain text.

All three are now clickable and open the same view. Opened from the history, the details that only apply to a ban currently in force — expiry, fail count — are not shown, because a history row is a past event.
