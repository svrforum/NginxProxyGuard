## 🔐 보안

### SSO에서 그룹을 빼도 접근이 유지되던 문제

공급자 설정의 **필수 그룹(required group)** 은 지금까지 **새 계정을 만들 때만** 확인됐습니다. 이미 SSO로 한 번 연결된 사용자는 그 검사를 건너뛰고 바로 로그인됐습니다.

즉 **IdP에서 사용자를 그룹에서 제외해도 NPG 접근 권한이 회수되지 않았습니다.** 퇴사자나 권한을 내린 계정이 계속 들어올 수 있었다는 뜻입니다.

그룹-역할 매핑도 마찬가지였습니다. 일치하는 그룹이 있을 때만 역할을 바꿨기 때문에, 관리자를 IdP의 관리자 그룹에서 제외해도 NPG 관리자 역할이 그대로 남았습니다.

이제 **로그인할 때마다 IdP의 그룹 상태를 기준으로 다시 판단합니다.**

- 필수 그룹에서 빠짐 → **로그인 거부**
- 관리자 그룹에서 빠짐 + 기본 역할 있음 → **기본 역할로 강등 후 로그인**
- 역할 동기화가 실패함 → **세션 발급 거부** (예전 권한으로 들여보내지 않습니다)

**기존 설치 호환성**을 위해 한 가지는 남겨 두었습니다. 그룹 매핑은 있는데 **기본 역할이 지정되지 않은** 공급자는, 일치하는 그룹이 없어도 로그인을 막지 않고 **기존 역할을 유지**하며 경고 로그를 남깁니다. 자동 계정 생성(JIT)을 끈 설치는 기본 역할이 없는 것이 정상 상태라, 여기서 거부하면 SSO로만 접속하던 관리자가 잠길 수 있기 때문입니다. 로그를 보시고 기본 역할을 지정해 두시길 권합니다.

거부된 이유는 로그와 알림에서 구분됩니다 — **그룹이 맞지 않음**인지, **그룹 정보 자체가 오지 않음**(스코프 설정 문제)인지, **역할 동기화 실패**인지.

> 제보와 수정까지 보내 주신 **@heygoodluck** 님 감사합니다. (#257)

### 리다이렉트 호스트 입력값 검증

리다이렉트 호스트의 도메인·대상·경로는 nginx 설정의 `server_name`과 `return` 지시어에 **그대로 들어갑니다.** 그런데 형식 검사가 없어서, 리다이렉트 편집 권한을 가진 사용자가 세미콜론이나 줄바꿈, `$변수` 를 넣어 **설정 문맥을 벗어난 지시어를 주입**하거나 요청 헤더·쿠키 값을 외부 주소에 실어 보낼 수 있었습니다.

`nginx -t` 는 문법만 보기 때문에 문법적으로 멀쩡한 악성 지시어는 걸러내지 못합니다. 그래서 값이 템플릿에 닿기 전에 검사합니다 — API 요청, 저장, 백업 복원, 그리고 설정 생성 직전까지 네 지점에서요.

**정상적으로 쓰시던 값은 그대로 동작합니다.** `nas.example.com:5001` 같은 포트 지정, 대괄호 IPv6(`[2001:db8::1]:8443`), 끝점 FQDN, 경로의 `#조각` 모두 허용됩니다.

혹시 예전에 저장된 값 중 검사를 통과하지 못하는 행이 있어도 **그 행만 건너뛰고 로그를 남깁니다.** 다른 리다이렉트나 프록시 호스트 설정, 백업 복원 전체가 함께 실패하지 않습니다.

## 🔐 Security

### Removing someone from an SSO group did not revoke their access

A provider's **required group** was only checked when an account was **created**. Anyone whose SSO identity was already linked skipped that check and signed straight in.

So **removing a user from the group at the identity provider did not take their NPG access away.** A departed colleague, or an account you had deliberately restricted, kept getting in.

Group-to-role mappings had the same shape: the role was only changed when a group matched, so removing an administrator from the provider's admin group left their NPG administrator role untouched.

Group membership is now **re-evaluated on every sign-in**:

- Removed from the required group → **sign-in refused**
- Removed from the admin group, a default role exists → **demoted to it, then signed in**
- Role synchronisation fails → **no session issued** (never a fall back to the old role)

**One allowance for existing installs.** A provider that has group mappings but **no default role** keeps the user's existing role instead of refusing, and logs a warning. Installs with just-in-time provisioning turned off legitimately have no default role, and refusing there could lock out an administrator who only signs in through SSO. Watch for that warning and set a default role.

Refusals are distinguishable in the log and in notifications: **group did not match**, **the group claim never arrived** (a scope configuration problem), or **role sync failed**.

> Thanks to **@heygoodluck** for the report and the fix. (#257)

### Redirect host values are validated before they reach nginx

A redirect host's domains, target and path are interpolated **directly** into the `server_name` and `return` directives. With no format checking, someone able to edit redirects could use a semicolon, a newline or a `$variable` to **inject directives outside the intended context**, or to put request headers and cookies into an outbound redirect.

`nginx -t` only checks syntax, so a syntactically valid malicious directive passes it. The values are therefore checked before they reach the template — at the API, on save, on backup restore, and immediately before config generation.

**Values you already use keep working.** A port (`nas.example.com:5001`), a bracketed IPv6 address (`[2001:db8::1]:8443`), an absolute FQDN and a `#fragment` in the path are all accepted.

If a stored row does fail validation, **only that row is skipped**, with a loud log line. Other redirects, proxy host configs and the rest of a backup restore are no longer taken down with it.

> Thanks to **@heygoodluck** for the report and the fix. (#256)
