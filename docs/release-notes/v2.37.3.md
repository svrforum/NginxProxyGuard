## 🩹 수정

### SSO 공급자 주소 끝의 `/` 때문에 연결이 실패하던 문제

Authentik처럼 발급자(issuer) 주소가 `/`로 끝나는 공급자를 등록하면 로그인 버튼을 눌렀을 때 **"공급자에 연결할 수 없습니다"** 로 끝났습니다. OpenID Connect 규격은 발급자 주소를 글자 그대로 비교하는데, NPG가 끝의 `/`를 임의로 떼어내고 있었기 때문입니다.

문제는 공급자마다 표기가 다르다는 점입니다. Authentik의 설정 문서는 `/`로 끝나고, Dex는 그렇지 않습니다. 그래서 무조건 떼면 Authentik이 깨지고, 무조건 두면 `/`를 실수로 붙여 넣은 분들이 깨집니다.

이번 릴리즈부터는 **입력한 그대로 먼저 시도하고, 실패했을 때만 반대 형태로 한 번 더 시도합니다.** 어느 쪽으로 적어도 연결되며, 재시도로 성공한 경우에는 어떤 형태가 맞았는지 로그로 알려 드리니 설정을 고쳐 두시면 됩니다.

> 제보와 함께 수정 코드까지 보내 주신 **@Messier333**, **@leekd123** 님 감사합니다. (#241)

### SSO 로그인이 거절될 때 이유를 알 수 없던 문제

기존 계정 연결이 안 될 때 화면에는 계정을 찾을 수 없다는 안내만 나오고, 컨테이너 로그에도 원인이 남지 않았습니다. 이제 거절된 이유 — 공급자가 이메일을 주지 않았는지, 이메일이 **검증되지 않은** 상태인지, 자동 계정 생성이 꺼져 있는지 — 를 `docker logs`에서 확인할 수 있습니다. 개인정보 보호를 위해 이메일 주소 자체는 기록하지 않고, 있었는지 여부만 남깁니다.

계정 연결에는 **검증된 이메일**이 필요합니다. Authelia를 쓰신다면 사용자 정보에 `email_verified: true`가 포함되는지 확인해 주세요. (#240)

> **api** 이미지를 받아 다시 올리세요:
> ```bash
> docker compose pull && docker compose up -d
> ```

## 🩹 Fixes

### A trailing `/` in the SSO issuer URL broke the connection

Registering a provider whose issuer URL ends in `/` — Authentik's does — ended at **"could not reach the identity provider"** when you pressed the sign-in button. OpenID Connect compares the issuer as an exact string, and NPG was stripping the trailing slash on its own.

The catch is that providers disagree about the shape. Authentik's setup page shows it with the slash; Dex's without. Always trimming breaks Authentik; never trimming breaks anyone who typed a stray slash.

From this release NPG **tries the URL exactly as you entered it, and only retries the other shape if that fails.** Either form connects, and when the retry is what worked, the log says which shape the provider accepted so you can correct the setting.

> Thanks to **@Messier333** and **@leekd123**, who reported this and sent the fix. (#241)

### No way to tell why an SSO sign-in was refused

When linking an existing account failed, the screen said only that no account was found, and the container log said nothing at all. The refusing condition is now visible in `docker logs`: whether the provider sent no email, whether the email came back **unverified**, or whether just-in-time account creation is off. The address itself is never logged — only whether one was present.

Linking requires a **verified** email. On Authelia, check that your user info includes `email_verified: true`. (#240)

> Pull the **api** image and recreate:
> ```bash
> docker compose pull && docker compose up -d
> ```
