## 새 기능

- 접근 목록에 아이디·비밀번호(기본 인증)를 넣을 수 있습니다. 이 목록을 쓰는 호스트는 접속할 때 아이디와 비밀번호를 묻습니다. "조건 완화"를 켜면 목록에서 허용한 IP는 비밀번호 없이 들어오고, 끄면 IP와 비밀번호가 둘 다 맞아야 합니다. ForwardAuth를 쓰는 호스트에는 붙일 수 없고, 이 목록을 쓰는 호스트의 국가·클라우드 챌린지는 차단으로 바뀝니다. (#387)
- 설정 → 에러 페이지에서 NPG의 차단 화면(403)과 백엔드 오류 화면(502·503·504)을 직접 만든 HTML로 바꿀 수 있습니다. 모든 호스트에 적용되며, 보안을 위해 이 페이지에서는 스크립트가 실행되지 않습니다. (#335)

## 수정

- 접근 목록에서 거부된 접속에 NPG 차단 화면 대신 nginx 기본 403 화면이 나오던 문제를 고쳤습니다.
- 로그 상세에서 공격 차단(Exploit) 규칙이 이름 없이 ID로만 보이던 문제를 고쳤습니다. (#390)

## New features

- Access lists can hold usernames and passwords (basic auth). Hosts using the list ask for them. With "Satisfy Any" on, an IP the list allows gets in without a password; with it off, both the IP and the password must match. A host with ForwardAuth cannot use such a list, and the GeoIP and cloud provider challenges of the hosts using one block instead. (#387)
- Settings → Error Pages replaces NPG's block page (403) and backend error pages (502, 503, 504) with your own HTML, on every host. For security, scripts do not run on these pages. (#335)

## Fixes

- A visitor an access list refused got nginx's plain 403 page instead of NPG's block page.
- The log detail showed an exploit block rule only by its ID, not its name. (#390)
