## 새 기능

- Let's Encrypt 인증서를 ECDSA 키(P-256, P-384)로 발급할 수 있습니다(#364). 인증서 화면이나 프록시 호스트의 SSL 탭에서 새 인증서를 만들 때 "키 종류"를 고르면 되고, 갱신해도 처음 고른 종류가 유지됩니다. 기본값과 기존 인증서는 RSA 2048 그대로입니다.

## 고침

- 업스트림(로드 밸런싱)을 쓰는 호스트를 복제하면 복제본이 원본과 같은 업스트림 이름을 써서 설정 적용이 실패하던 문제(#362). 그 뒤 전체 동기화를 하면 원본 호스트의 설정이 빠져 접속이 끊길 수 있었습니다. 이제 복제본은 자기 이름을 쓰고, 이미 겹친 이름은 업그레이드하거나 백업을 복원할 때 자동으로 바로잡습니다. 복제하면 업스트림의 https가 http로 바뀌던 문제도 함께 고쳤습니다.
- 필터 구독 목록이 25,000개에서 잘리는데 아무 표시가 없어 표시 오류처럼 보이던 문제(#361). 이제 목록 하나가 전체 상한인 100,000개까지 쓸 수 있고, 잘리면 "188,000개 중 100,000개 적용(상한)"처럼 보여 줍니다(기존 구독은 다음 갱신 뒤부터). 항목 10만 개면 nginx가 메모리를 100MB 정도 씁니다.
- 챌린지 검증 도중 호스트가 지워지면 500 대신 404를 돌려줍니다(#356).
- 길이 제한이 있는 값을 너무 길게 보내면 500 대신 400을 돌려줍니다(#353).

## 보안

- Echo 프레임워크를 v4.16.3으로 올렸습니다(클라이언트 IP 위조 관련 권고 2건). NPG는 클라이언트 IP 판정을 직접 설정하고 있어 영향은 없었습니다.

## New

- Let's Encrypt certificates can be issued with an ECDSA key, P-256 or P-384 (#364). Pick the key type when you create a certificate, on the certificates page or in a proxy host's SSL tab; renewals keep it. RSA 2048 stays the default, and existing certificates keep it.

## Fixed

- Cloning a host that uses an upstream (load balancing) gave the clone the source's upstream name, so its configuration failed to apply (#362). A full sync after that could drop the source host's configuration and take it offline. A clone now gets its own name, and names that already clash are fixed when you upgrade or restore a backup. A clone also no longer turns an https upstream into http.
- A filter subscription list was cut at 25,000 entries with nothing saying so, which looked like a display error (#361). One list can now use the whole 100,000-entry limit, and a list that is cut shows "100,000 of 188,000 entries applied (limit)" (existing subscriptions after their next refresh). 100,000 entries take about 100 MB of nginx memory.
- Challenge verification answers 404 instead of 500 when the host is deleted mid-verification (#356).
- An over-long value for a length-limited field answers 400 instead of 500 (#353).

## Security

- Echo is updated to v4.16.3 (two advisories about spoofed client IPs). NPG sets its own client IP handling, so it was not affected.
