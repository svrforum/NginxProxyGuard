## ⚠️ 보안 업데이트 — 바로 업그레이드하세요

nginx를 1.30.7로 올렸습니다. 1.30.6까지의 nginx에서 원격 코드 실행이 가능한 취약점들이 공개됐습니다(nginx2root). NPG는 SSL 호스트에 HTTP/2를 항상 켜기 때문에, SSL 호스트가 하나라도 있으면 로그인 없이 공격받을 수 있습니다. HTTP/3를 켠 호스트도 해당됩니다.

- HTTP/2: CVE-2026-123007, CVE-2026-123633
- HTTP/3: CVE-2026-121810
- 그 밖에 nginx 1.30.7의 보안 수정(resolver, SSL 요청 본문 무한 루프, alias/try_files, stream)이 함께 들어갑니다.

공개된 공격은 리눅스 커널의 SCTP 취약점과 엮어 컨테이너 밖 서버의 root 권한까지 얻습니다. 커널 패치가 나오기 전까지, SCTP를 쓰지 않는 서버라면 호스트에서 막아 두세요. 이미 올라와 있다면(`lsmod | grep sctp`) 재부팅해야 적용됩니다.

```bash
echo "install sctp /bin/false" | sudo tee /etc/modprobe.d/disable-sctp.conf
```

> ```

## ⚠️ Security update — upgrade now

nginx is now 1.30.7. Vulnerabilities allowing remote code execution in nginx up to 1.30.6 have been published (nginx2root). NPG always turns on HTTP/2 for SSL hosts, so an install with even one SSL host can be attacked without logging in. Hosts with HTTP/3 on are affected too.

- HTTP/2: CVE-2026-123007, CVE-2026-123633
- HTTP/3: CVE-2026-121810
- The other security fixes in nginx 1.30.7 (resolver, an endless loop reading request bodies over SSL, alias/try_files, stream) come along.

The published attack chains these with a Linux kernel SCTP flaw to get root on the server, outside the container. Until your kernel is patched, block SCTP on the host if you don't use it. If it is already loaded (`lsmod | grep sctp`), it takes a reboot.

```bash
echo "install sctp /bin/false" | sudo tee /etc/modprobe.d/disable-sctp.conf
```
