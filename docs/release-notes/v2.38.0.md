## ✨ 새 기능

### 차단된 IP를 눌러 그 IP가 무엇을 했는지 보기

차단 IP 목록에서 주소를 누르면 지금까지는 최근 로그만 나왔습니다. 이제 그 위에 **요약**이 붙습니다.

- **국가** — 접속이 어디서 왔는지
- **총 요청 / 차단된 요청** — 얼마나 두드렸고 그중 얼마가 막혔는지
- **누적 차단 횟수** — 이 주소를 몇 번이나 차단했는지
- **첫 목격** — 언제부터 보이기 시작했는지
- **주요 표적** — 어떤 호스트와 경로를 노렸는지

기간은 **1일 / 7일 / 30일** 중에 고를 수 있고 기본은 7일입니다. 요청 수치는 고른 기간 기준이지만, **누적 차단 횟수는 전체 기간**입니다 — "이 녀석은 벌써 네 번째"가 알고 싶은 값이기 때문입니다.

기간을 자유롭게 지정하지 않고 세 가지로 정해 둔 이유가 있습니다. 로그는 압축 저장되는데 압축된 구간에서는 IP 인덱스가 동작하지 않아, 기간을 열어 두면 로그 전체를 훑게 됩니다. 세 기간 모두 실측 100~130ms로 응답합니다.

### 계정에 실제 이메일 주소 지정

SSO(구글·Authelia·Authentik 등)로 **기존 계정에 로그인을 연결**하려면, 공급자가 알려주는 이메일과 NPG 계정의 이메일이 같아야 합니다. 그런데 지금까지 NPG는 이메일을 **물어본 적이 없었습니다.**

- 초기 설정은 사용자명과 비밀번호만 받았고
- 관리자가 만든 계정은 `사용자명@localhost`가 자동으로 붙었으며
- 이메일을 바꿀 수 있는 화면도 API도 없었습니다

그래서 계정 연결 기능이 **실제 설치에서는 한 번도 동작할 수 없었습니다.** SSO를 붙이려던 분들이 "계정을 찾을 수 없습니다"에서 막힌 원인입니다.

이번 릴리즈부터:

- **초기 설정**에서 이메일을 받습니다(선택 항목)
- **사용자 추가**에서 이메일을 지정할 수 있습니다
- **설정 → 사용자**에서 사용자를 누르면 현재 이메일이 보이고 바꿀 수 있습니다. NPG가 자동으로 붙인 주소에는 **"SSO 불가"** 표시가 붙습니다

이메일 변경은 **관리자만** 할 수 있습니다. SSO는 이메일로 계정을 찾은 뒤 공급자의 그룹 정보로 역할을 맞추기 때문에, 각자 자기 이메일을 정할 수 있으면 권한이 낮은 사용자가 관리자의 주소를 미리 선점해 관리자가 처음 로그인할 때 그 권한을 가져갈 수 있습니다.

이미 쓰고 계신 분은 **설정 → 사용자 → (계정 선택) → 이메일 수정**으로 공급자에 등록된 주소를 넣으시면 다음 SSO 로그인에서 바로 연결됩니다.

> 끝까지 확인해 주신 **@ydrob** 님 감사합니다. (#240)

## 🔒 보안

이메일 주소는 이제 **대소문자를 구분하지 않고** 유일해야 합니다. SSO 연결은 소문자로 바꿔 비교하는데 기존 제약은 대소문자를 구분해서, 대소문자만 다른 두 계정이 동시에 존재할 수 있었고 그럴 경우 연결이 둘 중 아무 계정이나 고를 수 있었습니다. 계정이 뒤바뀔 수 있는 형태라 막았습니다. 혹시 그런 계정 쌍이 이미 있다면 인덱스가 만들어지지 않고 경고만 남으며, 연결은 임의로 고르는 대신 거부합니다.

## ✨ New

### Click a banned IP to see what it has been doing

Clicking an address in the banned IP list used to show only its recent log lines. There is now a **summary** above them.

- **Country** — where the traffic came from
- **Total / blocked requests** — how much it asked for, and how much was refused
- **Times banned** — how often this address has been banned
- **First seen** — when it started showing up
- **Top targets** — which hosts and paths it went after

The window is **1, 7 or 30 days**, defaulting to 7. Request figures cover the window you pick, but **times banned covers all time** — "this one is already on its fourth ban" is the thing worth knowing.

The window is a fixed set rather than free-form for a reason: logs are stored compressed, and the IP index does not apply inside compressed chunks, so an open-ended range would walk the entire log. All three windows answer in 100–130ms measured.

> Thanks to **@heygoodluck** for the suggestion. (#242)

### Accounts can have a real email address

Linking an SSO sign-in (Google, Authelia, Authentik…) to an **existing** account matches the email your provider reports against the one on the NPG account. NPG, however, never **asked** for an email.

- Initial setup took a username and password only
- Admin-created accounts got `<username>@localhost` automatically
- Nothing in the UI or the API could change it

Which means account linking could never work on a real install. That is why people wiring up SSO hit "no account found".

From this release:

- **Initial setup** offers an email (optional)
- **Add user** accepts one
- **Settings → Users** shows the address on each account and lets you change it. Addresses NPG made up are marked **"No SSO"**

Changing an email is **admin-only**. SSO finds the account by email and then syncs the role from the provider's groups, so if everyone could set their own address, a low-privilege user could claim an administrator's address before that administrator first signs in and take the role with it.

Already running NPG? **Settings → Users → (pick the account) → edit the email**, set the address your provider holds, and the next SSO sign-in links straight away.

> Thanks to **@ydrob** for staying with it. (#240)

## 🔒 Security

Email addresses must now be unique **case-insensitively**. SSO linking compares them lower-cased while the old constraint was case-sensitive, so two accounts differing only in case could both exist — and the link would then pick either one. That is an account-mix-up shape, so it is closed. If such a pair already exists the index is skipped with a warning, and linking refuses rather than guessing.
