## 새 기능

- 호스트마다 저장하지 않을 접근 로그를 정할 수 있습니다(#347). 호스트 전체, 또는 지정한 상태 코드(207, 3xx 등)·메서드·경로로 시작하는 요청을 저장하지 않습니다. 로그 > 접근 로그 위쪽의 "수집 규칙" 버튼에서 설정합니다. NPG가 차단한 요청과 WAF 이벤트는 항상 저장하며, fail2ban에는 영향이 없습니다. 저장하지 않은 요청은 로그와 통계에서 빠집니다.
- URI 차단 규칙마다 허용 IP를 둘 수 있습니다(#343). 그 규칙에서만 통과하고, 모든 규칙에 적용되는 예외 IP와는 따로입니다. 예를 들어 로그인 경로만 사무실 IP에 열어 둘 수 있습니다.

## 고침

- 클라이언트가 보낸 헤더 때문에 일부 요청이 접근 로그와 fail2ban 집계에서 빠지거나, 로그의 차단 사유가 지워질 수 있던 문제.

## New

- Each host can leave access log lines out of storage (#347): all of them, or the requests with given status codes (such as 207 or 3xx), methods or path prefixes. Set it with the "Collection rules" button at the top of Logs > Access Logs. Requests NPG blocks and WAF events are always stored, and fail2ban is not affected. Lines that are not stored are missing from the logs and the statistics.
- A URI block rule can have its own allowed IPs (#343). They get through that rule only, unlike the exception IPs, which apply to every rule. A login path, for example, can stay open to one office address.

## Fixed

- Because of headers the client sent, some requests could be left out of the access logs and the fail2ban count, or lose their block reason in the logs.
